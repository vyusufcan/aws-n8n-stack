AWS Infrastructure Overview

n8n + k3s split stack

This environment separates stateful storage, the k3s control server, and the n8n application layer so the app can be recreated without losing workflow data.

Public Entry HTTPS traffic lands on an Application Load Balancer and is routed to n8n.vyusufcan.cloud or chat.vyusufcan.cloud.
Private Dependency The app host reads k3s connection details from SSM Parameter Store during bootstrap.

Stack Layout

Four Terraform ownership boundaries

1. bootstrap Creates the S3 remote-state bucket.
2. storage Owns the persistent encrypted EBS volume for /srv/n8n.
3. k3s Provisions the standalone k3s EC2 server and publishes SSM parameters.
4. infra Builds the app EC2 host, ALB, Route53 records, IAM profile, and volume attachment.

Traffic And Trust

How requests and control flow move

  • Users access the stack through Route53 aliases pointing at the ALB.
  • The ALB accepts public HTTPS on port 443 and forwards to the app instance.
  • The app EC2 host serves n8n on port 5678 and the chat UI on port 80.
  • The k3s server can reach n8n directly, using the app instance security-group rule derived from the SSM private IP value.
  • SSH stays restricted to the operator public IP captured at apply time.

Operational Model

Why this shape is useful

  • infra/ can be destroyed and recreated without deleting the persistent workflow volume.
  • k3s/ and infra/ stay loosely coupled through SSM instead of hard-coded addresses.
  • The split keeps platform responsibilities clear: storage durability, cluster control, and app delivery are separate concerns.
  • The design is optimized for repeatable rebuilds while preserving data.
